./01 Reconnaissance

I started with a RustScan scan.

The scan showed that ports 22 and 80 were open.

I tried to find directories and files with FFUF.

I found /app. Visiting it showed Pluck 4.7.13 and redirected me to http://dreaming.thm/app/pluck-4.7.13/?file=dreaming.

Fuzzing deeper revealed some interesting PHP files.

I found admin.php and login.php. Visiting http://dreaming.thm/app/pluck-4.7.13/admin.php displayed the page below and redirected me to login.php.

./02 Initial Access

I looked for exploits for this specific version of Pluck and found one.

I still needed to authenticate to use the exploit. My initial thought was to fuzz deeper while checking the documentation, but I could not find anything useful. I then tried brute-forcing the POST request.

I was rate-limited. At that point, I tried default passwords and luckily found that password worked.

I could now try the exploit I found.

The exploit worked and the webshell was accessible. While digging through the machine, I found two files in /opt: getDreams.py and test.py. The latter revealed a password for the user lucien.

I used the password to connect to the server over SSH.

./03 Lucien to Death

I was now Lucien, so I began investigating what I could use to gain higher privileges. I found that Lucien could run getDreams.py as the user death without a password.

Reading /opt/getDreams.py showed Death's password, but it was redacted. I believed the real getDreams.py, located at /home/death/getDreams.py, would contain the password.

I found an interesting detail in the source code: it read an entry from the library database with subprocess using command = f"echo {dreamer} + {dream}". I could escape the echo command and run my own command, but first I needed access to the MySQL database.

Reading Lucien's Bash history revealed something useful.

I found MySQL credentials. Now I only needed to add a malicious entry to the database.

It was time to insert the malicious entry.

With the malicious entry in place, the Python script would effectively run:

echo "hello"; cat /home/death/getDreams.py; echo "pwn" + "ed"

sudo -u death /usr/bin/python3 /home/death/getDreams.py

This would print the source code of getDreams.py, including Death's password. Running the script as Death worked as planned.

I could now see the source code containing Death's password.

I used it and escalated my privileges to death. It was time to dig again and find a path to morpheus. After investigating, I found that I could read the contents of /home/morpheus.

It contained a readable Python script called restore.py.

./04 Death to Morpheus

The script imports copy2 from the shutil library and uses it to back up kingdom to /kingdom_backup/kingdom. Using pspy64, I found that cron ran restore.py.

Further investigation showed that Death had write permission to the Python 3.8 libraries. I could edit the copy2 function in the imported shutil library and run my own code.

I added a one-line reverse shell from revshells to the start of the copy2 function.

Just like that, I was Morpheus. After checking what Morpheus could run with sudo, I found the following.

Morpheus could run anything as root without a password.
